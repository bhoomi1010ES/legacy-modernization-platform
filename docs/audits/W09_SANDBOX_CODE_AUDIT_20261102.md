## How the sandbox is implemented

`phase6_service.execute_attempt` constructs a candidate in a Git worktree, snapshots tracked files, creates database rows for verifier identity/lease/evidence, and calls `verifier_service.execute` inline. `VerifierService.execute` delegates to `phase6_sandbox.execute`.

`phase6_sandbox.execute` reads administrator command configuration, runs `docker info`, resolves a local immutable image ID, then invokes `docker run` from the caller process. Files are sent as JSON over stdin, recreated in container `/work`, and processed by an image-independent Python harness supplied by the platform. No repository bind mount or explicit control-plane credentials are supplied to the container. The Docker flags enforce non-root execution, no network, read-only root, resource limits and scratch tmpfs. The harness runs commands/adapters and returns observations. The caller evaluates those observations and invokes a deterministic regex/AST reviewer. A `finally` block attempts forced container removal.

These are useful controls. The Docker controller still shares a process with the workflow/database logic, and several parts of the verification result can be defeated or misreported.

## Probe interpretation

The two negative audit probes completed against actual Docker, not mocks. Both reproduced a correctness defect. Both containers were removed. The tool-substitution probe deliberately supplied zero characterization cases; it is **not** a fully passing job or evidence of complete workflow bypass. It demonstrates that the individual unit/static/security check results can be made successful without running the claimed tools. The adapter probe independently demonstrates that the current image can return golden outputs without a candidate application.

The real image contains pytest 9.1.1, mypy 1.15.0 and Bandit 1.8.3. The shadowing finding does not arise from those packages being missing. Harness evidence nevertheless reports `Python 3.12.14` for all three tools and null unit counts in the marker probe.

No full hostile-code containment suite, real provider request, independent job verification, ZIP delivery, or regression suite was executed by this audit. Historical test counts in the blocker matrix are historical and have not been rerun here.
